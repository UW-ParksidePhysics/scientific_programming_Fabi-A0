Good afternoon. My project is an interactive constellation identification program called Constellation Explorer. The idea came from a conversation during the trip, where the question of how to make astronomy approachable for everyday people came up. Star charts are useful, but they are static and crowded, and they do not invite the user to engage with the sky in any real way. I wanted to build something different. Instead of just showing the answer, my program lets the user pick a constellation from a list, drag across the stars to trace its actual shape, and then tap any completed star to learn about it. That way the user is not just reading information. They are building the constellation themselves.

The community motivation behind this project comes from that gap in how astronomy is normally taught. Many people are curious about the night sky, but they feel overwhelmed when they try to find real constellations, because the sky holds so many stars and the patterns are not obvious. A tool that builds the shape one star at a time makes that first step easier. My personal motivation came from my own interest in space and astronomy, and from wanting to build something visual and interactive in Python. I liked that this project pulled together science, geometry, interface design, and coding all into one program; it was not just one type of skill being used.
To understand the problem, I broke it down into smaller questions. What data would I need in order to draw real constellations accurately? How could I let the user interact with those constellations in a way that stayed simple, even on a phone screen? And how could I organize the code so that the project would stay readable as it grew? These questions led me to split the project into six separate files, each with its own job. The main file runs the program loop and handles input. The renderer draws everything on screen. The layout file controls how the panels resize. The game state tracks which constellation is picked and which lines are finished. The data manager loads the stars and constellations. And the config file stores the settings, colors, and file paths. Splitting things this way let me work on one piece at a time without breaking the rest.

What you are seeing on the projector is the finished project running live on itch.io. The interface is split into four sections. A left panel with the constellation list, a center drawing zone where the user traces stars, a right panel with constellation details, and a bottom panel that shows star info after completion. This is what the user sees as they move through the program, from selecting a constellation, to tracing it, and then learning more about the individual stars. The reason it runs in the browser is that is was configured with pygbag, which lets a Python pygame project compile down to something that works on the web. So the same code that runs on a desktop also runs on a phone or in a browser tab.

The Python solution uses two JSON files to keep the astronomy data separate from the code. One stores constellation patterns including names, descriptions, star positions, and which stars connect by edges. The other stores the detailed information for each star, such as magnitude, distance, and spectral type. I also pulled in B-V color values from a CSV file so each star can be drawn in its real color, whether blue, white, yellow, orange, or red, depending on its surface temperature. In the code, the data manager loads all of this; the game state tracks user progress; the layout adjusts the screen sections to work in landscape or portrait mode; and the renderer draws everything with cached surfaces so the program stays smooth. The main file ties all of those parts together inside the event loop.

In total, I created around seventy functions and methods across the six files, and the full project is roughly fifteen hundred lines of code including comments. The main libraries I used were pygame for the window, drawing, and input handling, and asyncio so the program can also run in the browser through pygbag. I also used the built-in json, csv, os, sys, and math modules for data loading, file handling, platform detection, and distance calculations.
Overall, this project shows how Python can take real astronomy data and turn it into something interactive and educational. It teaches pattern recognition, gives real star information, and responds directly to the user's actions. That is what made this project meaningful to me. It was not just about writing code. It was about using code to make scientific ideas easier to approach.
